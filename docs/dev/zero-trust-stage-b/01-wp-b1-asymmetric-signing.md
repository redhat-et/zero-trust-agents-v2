# WP-B1: asymmetric signing and JWKS

**Plan reference:** §B.1 of the
[integration plan](../2026-11-06-zt2-docsclaw-integration-plan.md).
**Status:** implemented on `feature/stage-b1-es256-jwks`; Podman
evidence recorded below, OpenShift run pending.
**Branch:** `feature/stage-b1-es256-jwks`.

## Scope

Deliver §B.1 as one PR: ES256 signing with a `kid`, a published JWKS, and
every verifier moved off the shared secret, including both deploy
drivers. This package changes no authorization behavior; scenarios 1–6
must stay green before and after it.

Non-goals: RS256 (DocsClaw accepts ES256 or RS256; one algorithm is
enough), key rotation, multiple active keys, KMS/HSM backing. Agent
audiences are B2; profile wiring is B3.

## Decisions pinned

1. **ES256 only.** The signer emits `alg: ES256`, `typ: JWT`, and a
   `kid` header on every token it mints.
1. **The key is a file, never an environment variable.**
   - Podman: `$STATE_DIR/access-token-signing-key.pem`, generated by
     `start-services.sh` with `umask 077`, mounted read-only into the
     issuer only. No verifier receives it.
   - OpenShift: key `access-token-signing-key` in the existing
     `zt2-secrets` Secret, mounted at
     `/etc/zt2/access-token-signing-key.pem`.
   - Both drivers may override the path with
     `ACCESS_TOKEN_SIGNING_KEY_FILE`; the default is the path above.
1. **`kid` is the RFC 7638 JWK thumbprint** (SHA-256 over the required
   public members, base64url). The signing header and the JWKS entry
   carry the same value, so a second key can be added later without
   ambiguity.
1. **Verification paths differ by role.**
   - `document-service` fetches `$ACCESS_TOKEN_JWKS_URL` (default
     `http://token-issuer.zt-demo.svc:8080/.well-known/jwks.json`),
     caches for 60 seconds, and refetches once on an unknown `kid`.
   - `token-issuer` verifies its own subject token **in process** with
     the public key derived from its signing key. It must not call its
     own JWKS endpoint.
1. **Code lives in `internal/tokens`.** Add a `Signer` and a
   `JWKSVerifier`; no new module dependency. The ECDSA and JWK parsing
   already present in `token-issuer/jwks.go` should be reused rather
   than duplicated where the shapes match.
1. **ES256 JWS signatures are raw `r||s` (64 bytes), not ASN.1/DER.**
   Split the signature in half and call `ecdsa.Verify`; `ecdsa.VerifyASN1`
   rejects every conforming token. This is the single most likely
   implementation mistake in this package.
1. **Clean break on the shared secret.** Delete `ACCESS_TOKEN_SECRET`
   from code, config validation, both deploy drivers, the Secret
   template, and the user-facing docs. No alias, no fallback, no
   deprecation path.
1. **JWKS is unauthenticated but not on the demo listener.** It is
   public key material, so it belongs on the main listener (port 8080)
   next to `/token`; the loopback-only `:8090` listener still serves
   only `/demo-subject-token`.

## Interfaces consumed by later packages

- `tokens.NewSignerFromFile(path string) (*Signer, error)`;
  `(*Signer).Sign(claims Claims) (string, error)`;
  `(*Signer).Verify(token string) (Claims, error)`;
  `(*Signer).PublicJWKS() []byte`.
- `tokens.NewJWKSVerifier(url string) *JWKSVerifier`;
  `(*JWKSVerifier).Verify(token string) (Claims, error)`.
- Environment contract from the [index](00-index.md):
  `ACCESS_TOKEN_SIGNING_KEY_FILE`, `ACCESS_TOKEN_JWKS_URL`,
  `ACCESS_TOKEN_ISSUER`.

Claims semantics stay in the callers exactly as today: `exp` is
mandatory, `iss` must equal `ACCESS_TOKEN_ISSUER`, `demo_token_use`
decides the exchange branch, and document services keep the audience and
scope checks.

## Risks and gotchas

- **Key permissions.** The images run as a non-root user (distroless
  `nonroot`, UID 65532). A `0600` bind-mounted key owned by the host
  user is not readable there. Use
  `--userns=keep-id:uid=65532,gid=65532` on the issuer container; if the
  installed Podman lacks that syntax, fall back to `0444` and record the
  demo-only tradeoff in the PR rather than weakening the file silently.
- **OpenSSL 3 curve selection.** Generate with
  `openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256`; the
  older `ecparam -genkey` emits SEC1, which the parser must also accept
  or the driver must convert.
- **Two JWKS names collide.** `config.Config.JWKSURI` is SPIRE's OIDC
  JWKS. The access-token verifier URL needs its own name.
- **JWKS fetch from a document service.** On Podman, resolve the issuer
  through the network alias `token-issuer.zt-demo.svc`, not through a
  host port. On OpenShift, use the Service FQDN.
- **Issuer `iss` exactness.** Every token check compares `iss` to
  `ACCESS_TOKEN_ISSUER`; the default without `:8080` is wrong for both
  deployments and fails every request.
